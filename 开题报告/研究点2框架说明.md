# 研究点 2 框架说明

研究点 2：融合时序—语义对齐与机理知识的大语言模型生成式故障诊断方法

## 1. 框架在做什么

输入一段飞行数据窗口（约 3 s），模型输出两部分：先给出诊断依据，说明数据里有哪些显著变化、符合哪条故障机理；再按部件、轴、模式、程度四个字段给出结论。

```mermaid
flowchart LR
  A["研究点 1 的分层特征<br/>（传感层 / 控制层 / 估计层）"] --> B["按通道切 patch<br/>MLP 编码器 + 投影层"]
  B --> C["时序 token"]
  D["文本：任务说明<br/>属性—机理知识<br/>通道名称 + 统计文本"] --> E["大语言模型（Qwen）"]
  C --> E
  E --> F["诊断依据 → 结论<br/>（结论字段做约束解码）"]
```

训练分两个阶段：

| 阶段 | 训练哪些部分 | 用什么数据 | 目的 |
|---|---|---|---|
| 阶段一：对齐 | 只训练编码器和投影层，大语言模型冻结 | ChatTS 公开的合成数据，以及由训练集飞行数据自动生成的“信号—描述”问答（不需要故障标签） | 让大语言模型“看得懂”时序 token |
| 阶段二：诊断微调 | LoRA，加上编码器和投影层 | 带标签的故障样本，目标为“诊断依据—结论” | 学会诊断 |

## 2. 用一个样本走一遍

假设一个窗口来自“电机 1 效率下降、中档”的飞行。

**输入（提示）**

```
[系统] 你是多旋翼无人机故障诊断助手。机理知识：
  - 电机效率下降：该电机实际出力低于指令，控制器提高其指令进行补偿，对角电机指令相应变化。
  - 陀螺仪偏置：EKF2 的陀螺零偏估计向偏置方向漂移，姿态控制量出现持续偏差。
  - ……（每个属性取值一条，共十几条）
[用户] 模式：完整。以下为 3 s 窗口的飞行数据：
  【控制层】电机 1 指令（100 Hz 标准差 0.8）：<ts>…</ts>
  【控制层】电机 3 指令（100 Hz 标准差 0.7）：<ts>…</ts>
  【传感层】陀螺仪 x（100 Hz 标准差 0.01）：<ts>…</ts>
  【估计层】磁罗盘 x 新息（……）：<ts>…</ts>
  ……
  请给出诊断依据和结论。
```

`<ts>…</ts>` 的位置在送入模型时被替换成编码器输出的时序 token。

**输出**

```
依据：电机 1 指令相对基线上升约 9 个百分点，对角电机 3 指令下降约 2 个百分点，传感层与估计层通道无显著变化，符合“电机效率下降”的机理：该电机出力不足，控制器提高其指令补偿。
结论：部件=电机1；轴=—；模式=效率下降；程度=中
```

- **快速模式：** 提示里的“模式：完整”换成“模式：快速”，模型只输出最后一行结论。研究点 3 的分层部署用的就是这种模式。
- **训练目标怎么来：** 依据中的变化量由程序从数据中算出（相对基线的变化量和显著性检验），机理取自机理表，结论来自标签，按模板拼成训练目标。
- **评价时怎么核验：** 把模型生成的依据和结论解析出来，与程序计算结果和机理表对照，得到依据一致率。

## 3. 和 ChatTS 的关系

以 ChatTS 为基础是合理的。ChatTS 面向的是多变量时序加大语言模型，和本课题的数据形式一致；它的编码器是简单的 patch + MLP，适合小样本；它支持每个通道带名称输入，并且开源了代码和合成数据方法。

| | ChatTS | 本课题 |
|---|---|---|
| 时序编码 | patch + MLP，每个通道单独编码，通道名随数据给出 | 沿用 |
| 数值尺度 | 每个序列单独归一化，缩放系数和偏移量写进文本 | 改为按正常飞行统计量统一标准化（见第 4 节问题 1），文本里只放 100 Hz 的波动统计量 |
| 对齐数据 | 基于属性的合成时序数据 | 沿用，另加由飞行数据自动生成的问答 |
| 任务 | 通用的时序理解与问答 | 结构化故障诊断，加入机理知识与“诊断依据—结论”输出 |
| 基座模型 | Qwen2.5 14B | Qwen 1.5B–4B + LoRA |

需要注意：ChatTS 发布的模型权重是 14B 规模的，和本课题的 1.5B–4B 基座维度不同，所以只用它的代码和合成数据，编码器要从头训练。

## 4. 原框架的问题和改法

| # | 问题 | 改法 |
|---|---|---|
| 1 | **统计摘要文本和诊断依据重复。** 原方案的统计文本里写了“相对基线的偏移”等数值，而诊断依据也是用这些数值生成的。模型直接从文本里抄数就能写出依据，时序 token 几乎不起作用，“时序—语义对齐”也就失去了意义 | 时序数据按正常飞行的统计量统一标准化，幅值信息保留在时序 token 里；文本只放降采样会丢失的 100 Hz 波动统计量。依据中的变化量必须由模型从时序中读出 |
| 2 | **机理知识只是放在提示里。** 每个样本的提示里放的都是同一张表，模型很容易学会忽略它，说不清机理知识起了什么作用 | 诊断依据中除了写数据中的显著变化，还要写出与之相符的机理条目。机理知识由此进入推理过程，也可以核验 |
| 3 | **双电机划分**（实验阶段再定，开题报告中不涉及） | 见第 9 节 |
| 4 | **“程度”的含义不统一。** 不同故障的 k、b、σ 量纲不同，“重”档如果只在测试中出现，就无法外推 | 程度统一按研究点 1 的归一化强度（故障幅值 / 正常波动）分档；程度外推划分只对某一类故障留出重档，其他故障的重档保留在训练集中 |
| 5 | **没有“无故障”输出。** 研究点 3 的检测器报警后才调用诊断模型，但检测器会有误报 | 部件字段增加“无故障”取值，诊断模型可以纠正误报 |
| 6 | **两种模式没有切换方式。** 原文只说混入只输出结论的样本 | 提示中加入模式指令（完整 / 快速） |
| 7 | **通道太多。** 40–60 个通道，每个通道都带名称和统计文本，提示会很长 | 只保留研究点 1 显著性分析中对至少一类故障显著的通道 |
| 8 | **层级标识嵌入与通道名重复。** | 去掉单独的层级嵌入，层级直接写在通道名称前，如“【控制层】” |
| 9 | **对比基线不公平**（实验阶段考虑，开题报告中不写）。 原基线 ② 是同一编码器加扁平分类头，它天然无法输出未见组合，比较意义不大 | 改为同一编码器加逐属性分类头。它也能输出未见组合，能检验“生成式 + 机理知识”到底有没有带来提升 |

另外一个实施细节：ChatTS 的合成数据描述是英文，本课题的提示是中文，训练时应统一为一种语言。

## 5. 创新点（两个）

1. **机理知识引导的属性化生成式诊断方法。** 将结论分解为部件、轴、模式、程度逐字段生成，模型先给出以机理为依据的诊断依据，再给出结论，从而诊断训练中未出现的故障组合。
   - 区别于已有工作：属性化零样本诊断（Zhao 等[33]、Han 等[34]）是判别式匹配；生成式大模型诊断（AeroGPT、InstructTime、Guo 等[45]）输出整体类别，推理链也不与机理对照。
2. **数据驱动的可核验诊断依据。** 依据中的变化量由飞行数据计算得到，同一套依据同时用于阶段一的对齐问答、阶段二的推理链监督和最后的依据评价，每一句都能回溯到数据。
   - 区别于已有工作：Guo 等[45] 的推理链由 GPT-4o 生成，没有经过核验。

**不算创新点的部分：** patch-MLP 编码器、投影层、两阶段训练、LoRA 和约束解码都是多模态大模型的常规组件，在报告中作为采用的方法写明即可。

## 8. 输出结构的先例与依据

输出结构拆开看，每一部分都有先例；把它们组合起来，用在无人机闭环飞行数据上，是本课题的新做法。

| 组成部分 | 先例 | 说明 |
|---|---|---|
| 把诊断（分类）写成文字生成 | InstructTime[36]、AeroGPT[48] | 都由大语言模型直接生成类别文字，而不接分类头 |
| 按属性描述故障，用属性组合识别未见故障 | 视觉领域：Lampert 等的属性零样本分类（TPAMI 2014）、Misra 等的属性—物体组合识别（CVPR 2017）；故障诊断领域：Feng 和 Zhao 的基于故障描述的属性迁移（IEEE TII, 2021, 17(3): 1852–1862）、Zhao 等[33]、Han 等[34] | 核心思路是“类别由共享的属性组成，见过各个属性，就有可能识别新的组合”。这是“按部件、轴、模式、程度输出”的直接依据。这些工作都是判别式的，本课题改为生成式 |
| 先写依据，再给结论 | 思维链 Wei 等[47]；故障诊断中的思维链蒸馏 Guo 等[45]；逐步蒸馏 Hsieh 等[52] | Guo 等[45] 加入推理链后，跨设备诊断准确率从 87.8% 提高到 94.8%，在泛化场景提升最明显 |
| 依据中引用知识或因果链 | 知识图谱与大模型结合的故障诊断，如程玉杰等[35]；S2S-FDD[32] 结合维修文档做树状诊断 | 诊断时引用领域知识作为推理的中间步骤 |
| 依据由程序生成、严格对应数据 | ChatTS[39] 的属性合成数据 | 描述按采样的属性取值生成，与时序严格对应。本课题把这一思路用于诊断依据 |
| 字段只能取预定义值 | Geng 等的语法约束解码（EMNLP 2023） | 约束解码在结构化任务上明显优于不加约束，数据少时更明显 |

**合理性的依据：**
- 属性零样本学习说明了为什么属性分解能识别新组合；
- 生成式分类说明了大语言模型可以直接输出属性文字；
- Guo 等[45] 的结果说明推理链对泛化有帮助。

**风险：** 生成式模型并不天然具备组合泛化能力。Lake 和 Baroni（ICML 2018）的 SCAN 实验表明，序列模型在训练中没见过的组合上表现很差。这也是框架要在依据中引用机理、设置留出实验、并以逐属性分类模型作对照的原因。

**输出格式：** 采用“诊断依据—结论”两段式，机理写在依据里。这种格式与 Guo 等[45] 的“推理链—结论”一致，有直接先例；本课题的不同在于依据由数据计算并与机理对照，可以核验。

**建议补充的引用：** Feng 和 Zhao（2021）是属性化故障诊断的早期代表工作，可在 1.2.2 节介绍 Han 等[34] 时一并引用。

## 9. 双电机划分为什么要调整（实验阶段再定）

开题报告中不涉及这一点，等数据采集完成后再根据实际情况尝试。这里只记录问题，供做实验时参考。

原定 S2 划分：训练集只有单电机故障（电机 1、2、3、4 各自单独故障），测试集是双电机故障（1+2、1+3）。

问题在输出上。训练时，“部件”字段永远只写一个电机，模型从没见过“部件=电机1, 电机2”这种写两个部件的输出。生成式模型几乎不会写出训练中从未出现过的输出形式，所以测试时大概率只答出其中一个电机，按完全匹配算就是错的。这样 S2 的结果会接近零，说明不了任何问题。

改法：训练集中保留一种双电机组合，测试另一种。按 PX4 四旋翼 X 型的编号，1+2 是对角电机，1+3 是相邻电机（与平台文档表 4 一致）。例如：

| | 训练 | 测试 |
|---|---|---|
| 原方案 | 电机 1、2、3、4 单独故障 | 1+2、1+3 |
| 调整后 | 电机 1、2、3、4 单独故障，以及 1+2 | 1+3 |

调整后，模型在训练中学过“部件可以写两个电机”，也分别见过电机 1 和电机 3 的单独故障，但没见过 1+3 这个组合。这才是一个有意义的组合泛化测试。

对角和相邻两种组合的飞行表现不同：对角两电机同向旋转，主要影响偏航；相邻两电机主要影响俯仰或滚转。因此 1+3 并不是 1+2 的简单重复，测试是有区分度的。
