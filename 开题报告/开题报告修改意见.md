## 2. 研究点与逻辑关系

### 2.1 整体逻辑

原稿的逻辑链比较完整：1.2 节三条综述线末尾各有“不足”，对应 2.2 节的三个关键问题，再对应 2.1 节的三项研究内容。三项内容是递进关系：研究内容一为研究内容二提供输入表征和监督信号，研究内容二为研究内容三提供教师模型。

“可核验的诊断依据”实际上贯穿了三项内容：一负责生成依据，二负责让模型学会生成依据，三负责在压缩后保持依据质量。答辩时把这条线讲出来，可以避免三项内容被看作“数据—模型—部署”的简单拼接。

### 2.2 需要补强的论证

**属性化生成为什么需要大语言模型。** 原稿的论证是“按属性逐字段生成，所以能判断未见组合”。但逐属性多头分类器同样能输出未见组合，只用这一点说明不了大语言模型的必要性。论证的落点应该放在两处：属性—机理描述以文本形式为各属性取值提供共享先验；依据生成充当中间推理。实验上则以逐属性多头分类头作为核心基线（3.2.2 (5) 已补入）。这是评审最可能追问的问题。

**指标没有定义。** 3.2.3 的创新点用了“泛化保持率”“依据一致率”，但正文没有给出定义，建议在 3.3 中补一句说明（参考写法见批注）。

**数据集描述还不够具体。** “未见组合”怎么划分、属性取值有哪些、“轴”对电机故障如何定义，目前都没有写明。建议在 3.2.1 (3) 补一张故障集合与属性取值表。

## 5. 答辩可能被问到的问题

| 问题 | 回答要点 |
|---|---|
| 为什么要用大语言模型，多头分类器不行吗？ | 以多头分类器作为基线；大语言模型的增益来自机理知识注入和依据生成，用实验结果回答 |
| 软件注入的故障和真实故障一样吗？ | 注入点在原始测量和电机输出端，故障会完整经过闭环控制和状态估计，满足闭环表征研究的需要 |
| 只做悬停有什么意义？ | 先在受控工况下验证方法，RflyMAD 等数据集也以悬停为主要工况 |
| 未见组合怎么划分？ | 按飞行轮次划分；测试组合中的每个属性取值在训练集中都出现过，但组合本身没有出现过 |
| 依据是程序生成的，模型只是在背模板吗？ | 测试时依据由模型根据输入自己生成，再与实测数据核对；消融实验验证依据生成对结论准确率的作用 |
| 和 ChatTS 有什么区别？ | ChatTS 是通用时序理解模型；本文加入了分层表征、属性—机理知识和结构化输出，并研究轻量化后的泛化能力保持 |
| 三项内容之间是什么关系？ | 递进关系，以可核验依据贯穿始终 |
