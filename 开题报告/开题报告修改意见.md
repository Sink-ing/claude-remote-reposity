## 3. 研究点与逻辑关系分析

### 3.1 逻辑链检查

开题报告的逻辑应当是一条闭合链：**现有不足 → 关键问题 → 研究内容 → 创新点 → 预期成果 → 验证指标**。修订后的对应关系如下：

| 现有不足（1.2 节） | 关键问题（2.2） | 研究内容（2.1） | 创新点（2.3） | 成果（2.4） | 验证指标（3.3.1） |
|---|---|---|---|---|---|
| 真机带标签数据稀缺；多数方法以原始传感器为输入，忽略闭环补偿 | (1) 闭环补偿与状态估计掩盖故障特征 | (1) 数据集构建与闭环故障表征 | (1) 分层自参考故障表征 | 数据集 + 表征方法 | 可检测性热图；消融“去掉控制层或估计层” |
| 扁平类别输出无法泛化到未见组合；解释缺乏核验标准 | (2) 小样本下未见组合的泛化与依据可信性 | (2) 生成式诊断 | (2) 机理引导的属性化生成式诊断 | 诊断模型 | 未见组合完全匹配率、依据一致率 |
| 轻量化只看已见类别准确率；缺少分层时延设计 | (3) 压缩中泛化与依据质量的保持 | (3) 轻量化与分层部署 | (3) 依据可核验约束下的轻量化 | 轻量模型 + 部署方案 | 泛化保持率、依据一致率变化、显存、时延、误报率 |

**修订前这条链断在两处：**
- **“研究内容（1）”与“不足”脱节。** 原标题写的是“射频信号”和“预处理”，与“闭环补偿掩盖特征”这一不足、以及关键问题(1)都对不上。
- **“创新点”与“验证指标”脱节。** 创新点里出现了“泛化保持率”“依据一致率”，3.3 节却没有给出定义和测量方法。

### 3.2 三项研究内容之间的关系

```mermaid
flowchart LR
  A["研究内容一<br/>数据集 + 分层表征"] -- "分层表征 / 属性标签 / 依据文本" --> B["研究内容二<br/>生成式诊断（教师）"]
  B -- "教师模型 + 可核验依据" --> C["研究内容三<br/>轻量化 + 分层部署"]
  A -. "可检测性分析 → 通道精选、检测器指标" .-> C
```

关系是**递进式**：一为二提供输入和监督信号，二为三提供教师。这种结构的好处是主线清晰；风险是**前一项出问题会拖累后面所有工作**。答辩时最好主动说明三点：
- 研究内容一的数据采集已经开始，并且有初步结果（所以图 3 一定要补上）；
- 研究内容二不依赖研究内容三，单独就可以支撑一篇论文；
- “依据可核验”是贯穿三项内容的**统一线索**：一负责生成依据，二负责学会生成依据，三负责在压缩后保持依据质量。这条线索能让三项内容不再是“数据、模型、部署”的简单拼接，而是围绕同一个科学问题展开。建议在 1.1 节末尾和 PPT 的研究框架页都点出来。

### 3.3 研究边界需要写清楚

下面这些边界不写明，评审会替你补上，而且通常往最严格的方向理解：

- **工况**：只做悬停，还是包括机动飞行？
- **故障**：只做单故障，还是包括复合故障？只做软件注入，还是也有物理故障？
- **应用模式**：飞行日志的事后分析，还是在线诊断？1.1 节末尾写的是“服务于事后分析……并为后续在线诊断奠定基础”，这个定位很稳妥，全文应保持一致。

| 3.2.2-(2) 由数据计算的诊断依据作为生成目标 | ✅ **合并到上一条** | 这一点是区别于已有方法“自由文本解释”的关键，应作为创新点 2 的核心 |

| 3.2.3-(2) 检测器常驻、异常触发、按需解释的分层部署 | 合并 | 级联检测与诊断的架构比较常见，单独列为创新点比较勉强，并入创新点 3 |

### 4.2 修订后的 3 个创新点及答辩要点

**创新点 1：面向闭环补偿的分层自参考故障表征方法**
- 与已有工作的区别：已有数据驱动方法[19–23]直接使用原始传感器通道；基于模型的方法[15–17]需要自己设计观测器。本文**直接利用飞控已有的控制量和 EKF2 内部量**，不需要额外建模，同时具备“残差”的物理含义。
- 证据：图 3 的“故障 × 通道”显著性热图，以及消融实验（去掉控制层或估计层、去掉自参考差分）。
- 风险：评审可能认为这只是“特征工程”。答辩时应强调，本文给出的是对**闭环系统中故障特征如何在三层之间转移**的定量刻画，是规律性认识，而不只是选了几个特征。

**创新点 2：机理知识引导的属性化生成式故障诊断方法**
- 与已有工作的区别：
  - 相对于 FD-LLM[31]、BearLLM[44]、AeroGPT[48]：它们以类别名称为生成目标；本文**按属性逐字段生成**。
  - 相对于 Han[34] 及属性迁移类方法：它们在嵌入空间中做相似度匹配；本文是**生成式**输出，并且以**可核验依据作为中间推理目标**。
  - 相对于 Guo[45] 的 CoT 解释：它们的解释是自由文本，无法检验；本文的依据**可逐句回溯到具体数值**。
- 证据：未见组合设置下，本方法与**逐属性多头分类器**的对比（这是最关键的一组实验，一定要做），以及“去掉依据生成”“去掉机理描述”两组消融。
- 风险：如果多头分类器在未见组合上的效果接近本方法，创新点 2 的立论会被削弱。应提前准备分析思路：生成式方法的优势是否主要体现在小样本设置或依据质量上。

**创新点 3：依据可核验约束下的诊断模型轻量化与分层部署方法**
- 与已有工作的区别：Syn-Diag[53] 等方法只在已见类别上评估压缩效果；逐步蒸馏[52] 不检查教师依据是否正确。本文**用程序核验过滤教师输出**，并以未见组合泛化保持率作为评价目标。
- 证据：比较“过滤 vs 不过滤”两种蒸馏的依据一致率；比较不同压缩率下泛化保持率的变化曲线。

## 6. 答辩可能被问到的问题及回答要点

| 问题 | 回答要点 |
|---|---|
| 为什么一定要用大语言模型？小模型加多头分类不行吗？ | 多头分类器也能输出未见组合，所以我们把它作为核心基线。LLM 的增益来自两点：机理知识以文本形式注入，提供跨属性的共享先验；依据生成作为中间推理，提供可核验的解释。实验会直接回答这个问题 |
| 软件注入的故障和真实故障一样吗？ | 注入点设在原始测量和电机输出层，故障会完整经过闭环控制和状态估计，这是闭环表征研究所需要的。我们计划补充少量物理故障（切角桨叶）作为外部测试 |
| 只做悬停有什么意义？ | 悬停是故障诊断研究的标准工况（RflyMAD 也包含悬停），先在受控工况下验证方法。若时间允许，会补充巡航数据测试泛化能力 |
| “未见故障组合”是怎么划分的？会不会太简单？ | 按飞行轮次划分，测试组合的每个属性值在训练中都出现过，但组合本身没有出现过。可以说明具体留出了哪些组合 |
| 诊断依据是程序生成的，LLM 只是在背模板吗？ | 训练时依据是监督信号；测试时模型必须根据输入自己生成，再由程序与实测数据核对，所以依据一致率是客观指标。消融实验会验证依据生成对结论准确率的贡献 |
| 自参考差分在实际飞行中怎么获取基线？ | 本课题定位于飞行日志分析和准在线诊断；在线场景可以用滑动参考窗口或同机正常飞行统计量替代，并会做对比实验 |
| 没有真实机载平台，部署结论可信吗？ | 通过限制显存和线程数模拟资源约束，并引用文献[57]在 Jetson 上的实测规律作为参照；条件允许时会做实机测试 |
| 数据量有多大？够训练 LLM 吗？ | 采用 LoRA 参数高效微调，第一阶段可以借助合成数据对齐；风险预案中准备了软件在环仿真数据扩充 |
| 三项内容之间是什么关系？任意一项失败怎么办？ | 递进关系，以“可核验依据”贯穿始终；研究内容一已有初步结果；研究内容二可以单独成文 |
| 这项工作和 ChatTS 有什么区别？ | ChatTS 是通用时序理解模型；本文针对闭环飞行数据，加入了分层表征、属性—机理知识和结构化输出，并研究轻量化后的泛化保持问题 |
