## 一、题目

**推荐（第二轮按你的意见修订）：基于大语言模型的多旋翼无人机故障诊断与轻量化部署方法研究**

开题阶段题目宜宽：“小样本”“生成式”是研究内容里的方法特征，写在研究点和创新点里即可，不必进题目。题目宽，后续调整方法也不必改题；学校开题说明第五条也允许学位论文题目在开题基础上适当改动。

| 改动 | 依据 |
|---|---|
| “无人机” → “多旋翼无人机” | 实验对象是 F410 四旋翼，故障模型（电机效率、IMU/罗盘）都是多旋翼特有的。这一处建议保留，否则会被问“固定翼、垂起做不做”。若导师希望更宽，可退回“无人机”。 |
| 去掉“智能” | “智能”说不出具体含义，去掉后题目更干净；“故障诊断”本身已足够宽。 |
| 保留“轻量化部署” | 轻量化本来就是为部署服务的。研究点 3 写成“面向资源受限部署场景”，在 4090/CPU 上模拟资源约束来验证，实机部署放到后续条件允许时完成。 |

题目里写了“部署”，答辩时要能回答“部署到哪里、怎么验证”。准备好的答法是：目标是机载计算机（如 Jetson 一类）；现阶段在限定显存和 CPU 的条件下模拟资源约束，测显存、延迟和精度损失；具备硬件后再上机验证。

## 二、三个研究点

### 研究点 1：多旋翼无人机故障注入数据集构建与闭环故障特征表征方法

**要解决的问题**：闭环控制和状态估计会“吸收”故障：电机出力下降后控制器自动补偿，传感器故障被 EKF2 当成真实测量。所以故障在原始传感器信号上不明显，要在控制量、电机指令、新息、零偏估计这类量上才看得出来。没有一套能反映这种耦合的数据和表征，后面的模型无从学起。

| 采用 | 小点 | 依据 |
|---|---|---|
| ✓ 核心 | **1b 闭环补偿下的故障敏感表征** | 这是本点唯一能称为“科学问题”的部分，也是无人机区别于轴承的地方。你选话题时已经加了新息、检验比、零偏估计、电池电压，只需把思路写成方法：分析每类故障在哪些量上显现、显现多快，据此构造输入表征。 |
| ✓ 基础 | **1a 真机故障注入与数据集构建** | 平台已经建成并验证过，是很强的工作基础，但它是工程，所以作为本点的前半部分，不单独成点。 |
| ✓ 新增 | **属性化标签体系与评测划分** | 生成式诊断需要把标签拆成“部件 / 轴 / 模式 / 程度”，泛化实验也需要事先定好留出方式（见第三节）。这两样都属于数据集，放在本点，第 2、3 点直接沿用。 |
| ✓ 并入 | **1f 可检测性边界分析** | 你的采集流程本来就要通过预试确定档位，顺手把“各故障在哪些量上、多大强度可见”整理成结果，同时为“程度”字段提供依据。成本低，又能出图。 |
| ✓ 并入 | 1c 多速率对齐与切窗 | 必要的工作，但新意低，写在方法细节里，不列为小点。 |
| ✗ 不采用 | 1d 仿真—真机联合 | 你已决定不用仿真数据。 |
| → 移到点 2 | 1e 时序文本化 / token 化 | 它决定“怎么喂给 LLM”，属于模型设计，放在点 1 会和点 2 重叠。 |
| ✗ 不采用 | 1h 离线合成故障 | 离线叠加故障没有闭环响应（控制器不会补偿），正好违背本点的核心论点，自相矛盾。 |
| → 展望 | 1g RFID | 只在平台介绍里提一句“同步采集外部射频观测”，再写进展望。 |

### 研究点 2：融合时序—语义对齐与机理知识的大语言模型生成式故障诊断方法

**要解决的问题**：真机故障数据的获取成本高、有坠机风险，每类故障能采到的有标签样本有限，而且实际会出现训练时没见过的故障组合。分类头只能在已知类别里选，因此要让 LLM 借助语言先验和机理知识，对未见故障做出结构化判断。

| 采用 | 小点 | 依据 |
|---|---|---|
| ✓ 核心 | **2a 飞控时序与 LLM 语义空间对齐**（含 1e） | 时序编码器 + 投影层 + LLM（参考 InstructTime/InstructTime++、BearLLM、Tao 等）。无人机特殊处是多变量、多速率、闭环耦合，编码器直接接点 1 的表征。这是方法主体。 |
| ✓ 核心 | **2c 小样本 / 未见故障泛化** | 已确定的主打方向。泛化靠属性组合实现：部件、轴、模式见过，组合没见过，模型仍能拼出答案。分类头天然做不到，这正是“为什么用 LLM”的答案。 |
| ✓ 核心 | **结构化生成输出（2d + 2f 合并）** | 模型按固定模板输出“部件 / 轴 / 模式 / 程度 / 依据”。程度来自 2f，依据来自 2d，可解释性因此是诊断输出的一部分，不单独成点。用约束解码控制格式与幻觉，评价时把输出解析回各字段。 |
| ✓ 支撑 | **2b 机理知识注入** | 把“电机 i 效率下降 → 该电机指令升高、对角电机补偿”“陀螺偏置 → 零偏估计漂移”这类机理写成知识描述，放进提示或训练样本。未见组合要靠它推理，“依据”字段的正确性也要靠它核验（规则来自点 1 的分析）。 |
| ○ 基线 | 2g 纯提示 / 不微调 | 作为对照：证明“需要对齐训练”，而不是直接问 LLM 就行。 |
| ✗ 不采用 | 2e MoE 融合 | 容易被看成“套模块”，故障类别也只有两大类（执行器 / 传感器），MoE 的必要性不足。 |
| → 展望 | 2h 与 RFID 多模态 | RFID 不进研究内容。 |

**模型规模**：主模型选 1.5B–7B 的开源 LLM，LoRA 或 QLoRA 微调，4090 能跑，7B 需要时租 48G 卡。

**对照组**：① 1D-CNN / Transformer + 分类头；② 同一编码器 + LLM + 分类头；③ 纯提示 LLM；④ 本文生成式方法。② 与 ④ 的差别最关键，它单独证明了“生成式”的作用。

### 研究点 3：面向资源受限部署场景的故障诊断模型轻量化方法

**要解决的问题**：点 2 的模型是 1.5B–7B 级，显存和延迟都不适合资源受限设备。压缩时不能只保住已见故障的准确率，还要保住**未见故障的泛化能力和依据输出**。这也正面回答了“为什么不一开始就用小模型”。

| 采用 | 小点 | 依据 |
|---|---|---|
| ✓ 核心 | **3a 知识蒸馏** | 点 2 模型作教师，蒸馏到 0.5B 级小 LLM（仍是生成式），要蒸馏的是结构化输出和依据，不只是标签。可同时蒸馏一个分类头小网络作为极轻量的对照。 |
| ✓ 核心 | **3b 量化** | INT8 / INT4，在 4090 和 CPU 上测显存、延迟、精度损失。不需要机载硬件就能完整验证。 |
| ✓ 支撑 | **3d 时序 token 压缩** | 生成式模型的延迟大部分来自输入 token 的数量，而时序 token 数量又是由切窗和 patch 设计决定的，压缩它最直接。和点 2 的编码器设计衔接紧，工作量可控。 |
| ✓ 评价 | **3e 日志回放式在线诊断** | 用已采集的 ULog 按时间顺序回放、滑窗诊断，计算“注入时刻 → 正确输出”的检测时延。不需要硬件，又补上了离线分类和在线诊断之间的缺口。 |
| ○ 设计 | 3c 分层架构（轻量检测 + 按需诊断） | 题目写了“部署”，研究内容里需要有部署方案。所以作为部署架构写进点 3（轻量模型常驻检测、报警后调用压缩后的诊断模型），用日志回放验证流程；实机部署放到展望。 |
| ✗ 不采用 | 3f 端—云协同 | 和“轻量化”方向相反，会削弱本点。 |

**工作量提示**：本点是三者中最容易压缩的。如果点 2 进度拖后，可只保留 3a + 3b，3d 和 3e 作为加分项。

## 三、三点衔接与共用评价体系

**关系**：点 1 提供数据、标签体系、故障表征和评测划分 → 点 2 在此之上训练生成式诊断模型 → 点 3 把点 2 的模型作为教师进行压缩。三点用同一套数据划分和指标，才能前后对比。

**评测划分**（定义在点 1，三点共用；一律按飞行轮次划分，避免同轮窗口泄漏）：

| 划分 | 训练 | 测试 | 考察 |
|---|---|---|---|
| S1 常规 | 各故障部分轮次 | 其余轮次 | 已见故障的基本性能 |
| S2 部件组合 | 单电机 1–4 | 双电机 1+2、1+3 | 部件组合泛化（双电机需先完成实飞验证） |
| S3 轴留出 | 偏置故障的两个轴 | 第三个轴 | 轴属性泛化 |
| S4 程度外推 | 轻、中档 | 重档 | 程度外推 |
| S5 小样本 | 每类只取 1–k 轮 | 其余 | 训练样本数量对性能的影响 |

**指标**：
- 诊断：各字段准确率、整体完全匹配率、未见组合上的准确率；
- 依据：与机理规则的一致率（例如电机故障时是否指出了正确电机的指令升高）；
- 轻量化：参数量、显存、单次推理延迟、回放检测时延，以及压缩前后上述指标的变化。

## 四、提炼出的创新点（开题报告与 PPT 可直接用）

1. 构建了带同时钟标签的多旋翼真机故障注入数据集，揭示闭环补偿下故障在控制量与估计器内部量上的表征规律，并据此设计故障敏感的输入表征。
2. 提出属性化的结构化生成式诊断方法，通过时序—语义对齐与机理知识注入，实现对未见故障组合的小样本泛化，并同时输出诊断依据。
3. 提出保留泛化与依据能力的蒸馏—量化轻量化方法，并以日志回放评估在线诊断时延。

**展望**：RFID 射频外部观测的多模态融合；机载计算机上的分层诊断系统部署；真实老化故障（桨叶破损、电机磨损）上的验证。

## 五、风险与应对（仅列与收敛方案直接相关的）

| 风险 | 应对 |
|---|---|
| 生成式在 S1 上不如分类头 | 正常现象，论文立论放在 S2–S5；S1 持平即可。 |
| S2–S5 留出后测试样本偏少 | 采集时保证每个故障单元有多轮重复；结果报告多次随机种子的均值与方差。 |
| 双电机实飞失稳 | 档位从轻开始预试；若最终做不了，S2 改为“单电机：留出某个电机编号”。 |
| 生成格式不稳 / 幻觉 | 固定模板 + 约束解码；格式错误率作为一个指标报告。 |
| 开题时没有模型结果 | 用已有拆桨 / 实飞验证数据画 1–2 张“故障在控制量和新息上显现”的图，支撑点 1 的科学问题。 |
