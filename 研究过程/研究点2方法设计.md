## 2.1 时序信号以什么形式进入 LLM

| 方案 | 做法 | 来源 | 评价 |
|---|---|---|---|
| a 数值直接文本化 | 把采样值写成数字串 | LLMTime 一类工作 | 多通道时 token 数爆炸，LLM 对长数字串的理解也差，不适合 |
| b 统计摘要文本 | 把趋势、偏移、波动写成自然语言 | S2S-FDD 的信号→语义算子；Han 2026 用 LLM 把运行数据转成文本【文献夹】 | 可解释、与 LLM 天然兼容，但丢细节，单独用精度有限 |
| c 离散 token | patch 经 VQ 码本量化为离散 token | InstructTime / InstructTime++【文献夹】 | 统一成“词”，但码本要用大量数据训练，你的数据量偏少 |
| ★ d 连续嵌入 | patch → 编码器 → 投影到 LLM 词嵌入空间 | ChatTS、BearLLM、FD-MVLLM、HiTime（Tao 2025）【文献夹】 | 目前多模态 LLM 的主流做法，保留信号细节，数据需求比 c 少 |
| e 画成图片交给视觉 LLM | 曲线图 → Qwen-VL 类模型 | Guo 2026 用 Qwen2.5-VL【文献夹】 | ChatTS 的实验显示看图方式明显弱于专门的时序编码；图片 token 也多 |

**推荐 d 为主、b 为辅的混合输入。** 再借鉴 ChatTS 的两个细节（已核对原文 3.4 节）：
- **通道名随数据一起给出**：每个通道的时序 token 前加上通道名，例如“电机 1 指令：⟨ts⟩…⟨/ts⟩”。模型因此知道每段信号是什么量，“依据”里点名通道才有基础。
- **保留数值尺度**：归一化会丢掉幅值信息。ChatTS 的做法是把每个通道的缩放系数和偏移量以文本形式写进提示。对你来说，可以直接把研究点 1 的窗口统计量（相对基线的偏移、标准差）写进文本摘要，作用相同。

## 2.2 时序编码器

| 方案 | 做法 | 来源 | 评价 |
|---|---|---|---|
| a 1D-CNN | 多通道卷积 | 经典诊断网络 | 简单，但通道之间的身份信息混在一起，不利于点名通道 |
| ★ b 通道独立 patch + MLP | 每个通道单独切 patch，用小型 MLP 编码 | ChatTS 用 5 层 MLP 编码 patch，并指出简单结构已足够【文献夹】 | 参数少、适合小样本，每个 token 对应“某通道某时段”，可解释性好 |
| c patch + Transformer | 在 b 的基础上加一个小型 Transformer 建模时间依赖 | PatchTST 类结构；HiTime 的分层编码器【文献夹】 | 表达力更强，但参数更多、更容易过拟合 |
| ★ d 按层分组 | 传感层、控制层、估计层各一组编码参数，或加一个“层标识”嵌入 | Lin 2026 的多传感器嵌入层；HiTime 的分层编码【文献夹】 | 和研究点 1 的分层表征直接对应，写进论文逻辑连贯 |
| e 预训练时序基础模型（冻结） | 用 MOMENT、Chronos 一类通用时序模型做编码器 | 时序基础模型方向 | 可能缓解小样本问题，但它们多在预测任务上预训练，与故障特征不一定匹配；适合作为对比项 |

**推荐 b + d**：通道独立的 patch-MLP 编码，加上按层区分的标识嵌入；c 和 e 作为对比或消融。

**简单 MLP 够不够？（第二轮补充）**

够用的理由有三条：
1. **时间与通道间的关系由 LLM 负责建模。** MLP 只编码一个 patch（约 0.5 s）内部的形状，patch 之间的时间依赖、通道之间的耦合，都由 LLM 对全部时序 token 做自注意力来完成。LLM 本身就是一个很强的序列模型，编码器不必重复这件事。ChatTS 也明确指出，用简单 MLP 编码 patch 效果已经很好【文献夹】。
2. **最关键的跨通道关系已经由研究点 1 显式算好。** 电机指令不平衡量、相对基线的差分都直接作为输入通道，不需要编码器自己去学。
3. **小样本下参数少反而是优势**，过拟合风险更低。

风险和对策：
- 噪声类故障主要体现在 patch 内的高频波动，MLP 能捕捉方差变化，统计摘要里也有标准差，双重保障。Chen 2027 用了时域 + 频域的并行嵌入，并指出频域对机器人电流信号很重要【文献夹】；你的噪声故障是白噪声，频域优势不明显，因此频域分支作为备选，不作为默认。
- 消融实验里把 MLP 换成 patch-CNN 或小型 Transformer 做对比。如果复杂编码器明显更好，再升级。

开题报告里写成“轻量分块编码器（默认 MLP，可替换为卷积或 Transformer 结构）”，给后续调整留出空间。

token 数量的粗估：3 s 窗口在 50 Hz 下是 150 个点，patch 长度取 25 时每通道 6 个 token；按 40–60 个通道算，共约 240–360 个时序 token，4090 上完全可以接受。这个数字也是研究点 3 做 token 压缩的出发点。

## 2.3 训练与对齐策略

| 方案 | 做法 | 来源 | 评价 |
|---|---|---|---|
| a 单阶段端到端微调 | 编码器 + LoRA 一起直接训练诊断任务 | 常见基线 | 简单，但数据少时对齐不充分，容易记住标签而不是理解信号 |
| ★ b 两阶段 | 阶段一：冻结 LLM，只训编码器和投影层，学“信号→描述”；阶段二：LoRA + 编码器一起训练诊断任务 | InstructTime 的“对齐预训练 + 微调”；ChatTS 的对齐训练 + SFT；BearLLM【文献夹】 | 多模态 LLM 的标准流程；阶段一不需要故障标签，可以用上全部正常飞行数据 |
| c 对比学习对齐 | 让信号嵌入与属性文本嵌入在同一空间靠近（类似 CLIP） | Wang 2026 的分层跨模态对齐；Han 2026 的共享表示空间【文献夹】 | 对未见故障有帮助，但增加一个损失项和调参工作 |
| d 先训分类网络再对齐 | 先训练一个故障分类网络，再把它的特征接到 LLM | BearLLM【文献夹】 | 编码器会偏向已见类别，与“未见组合泛化”的目标冲突 |

**推荐 b**，c 作为可选的辅助损失（时间允许再加，或作为消融项）。

**阶段一的训练数据**可以全部由研究点 1 的模板自动生成，不需要额外标注。例如“电机 2 指令相对基线变化了多少？”“哪些通道的波动明显增大？”，答案都由程序算出。这和研究点 1 的“数据驱动模板”是同一套工具，复用程度高。

注意：做 S2–S5 留出实验时，测试轮次的数据在两个阶段里都不能出现，阶段一也不行。

## 2.4 机理知识注入

| 方案 | 做法 | 来源 | 评价 |
|---|---|---|---|
| ★ a 机理表放进系统提示 | 把研究点 1 的十几条属性—机理描述直接写进提示 | Zhao 2025 设计面向工业故障的提示【文献夹】 | 条目少，全放进去也就几百个 token，最简单直接 |
| b 检索增强（RAG） | 按需检索相关条目 | S2S-FDD 检索历史维护文档【文献夹】 | 知识库只有十几条，检索没有必要，属于过度设计 |
| ★ c 依据作为训练目标 | 让模型先输出依据再输出结论，相当于把机理推理写进监督信号 | Guo 2026 的思维链（CoT）蒸馏【文献夹】 | 机理知识通过训练进入模型，“依据”字段也同时得到训练 |
| d 领域文档继续预训练 | 用 PX4 文档、教材对 LLM 先做领域微调 | Zhao 2025 用诊断报告微调 LLM【文献夹】 | 需要较多文本，收益不确定，工作量大 |
| e 属性文本作为类别原型 | 用属性描述的文本嵌入构造分类器 | Han 2026【文献夹】 | 属于判别式路线，可作为零样本对照方法 |

**推荐 a + c。** 知识从两个方向进入模型：推理时靠提示，训练时靠依据。

## 2.5 输出形式与解码

| 方案 | 做法 | 来源 | 评价 |
|---|---|---|---|
| a 自由文本 | 模型自由回答 | — | 无法自动评价，幻觉不可控 |
| ★ b 结构化字段 | 固定模板输出各字段 | AeroGPT 的生成式故障分类；InstructTime 把类别写成文本输出【文献夹】 | 可解析、可逐字段评价 |
| ★ c 依据在前、结论在后 | 先写观察到的证据，再给部件 / 模式 / 程度 | 思维链做法 | 结论建立在证据之上，对未见组合更有利；代价是输出更长、推理更慢 |
| c′ 结论在前、依据在后 | 先给结论，再补解释 | — | 推理快，但解释容易变成事后附会 |
| ★ d 约束解码 | 用语法约束，让各字段只能取预定义的属性值 | 结构化生成工具（如 Outlines、XGrammar 一类） | 杜绝格式错误和编造的部件名。你的未见故障都是已知属性值的新组合，所以约束词表不会限制泛化 |

**推荐 b + c + d。** 输出示例：

```
依据：电机1指令相对基线上升约9个百分点；对角电机3指令下降；陀螺仪与罗盘通道无显著变化。
部件：电机1
轴：—
模式：效率下降
程度：中
```

双电机这类多故障，在“部件”字段里允许列出多个值（如“电机1, 电机3”）。“依据在前”带来的额外推理时间，留给研究点 3 去压缩。

**依据放在前面还是后面，有没有区别？（第二轮补充）**

有区别，而且文献里有直接证据：

| 做法 | 代表文献 | 结果 |
|---|---|---|
| 不输出依据，直接给结论 | AeroGPT、InstructTime【文献夹】 | 推理最快，但没有解释 |
| 依据在前（思维链） | Guo 2026 的 QwIndustryT：先生成推理链再给结论，推理链由 GPT-4o 生成后蒸馏【文献夹】 | 与不带推理链的同一模型（QwIndustry）相比，跨设备诊断平均准确率从 87.8% 提高到 94.8%，JNU 数据集从 96.0% 提高到 99.5%。**泛化场景提升最明显**，这正是你的主打方向 |
| 依据在后（事后解释） | — | 结论生成时看不到依据，依据容易变成为结论找理由，可信度弱 |
| 依据作为辅助任务，推理时可省略 | Distilling Step-by-Step（Hsieh 等, 2023）[网络](https://arxiv.org/abs/2305.02301)：训练时让模型分别学“输出依据”和“输出结论”两个任务，推理时只要结论 | 用更小的模型、更少的数据就能达到好效果，推理不增加耗时 |

**推荐**：主方法采用依据在前，因为你的核心目标是泛化，Guo 2026 的结果正好说明推理链在泛化场景收益最大。同时在训练数据里混入一小部分“只输出结论”的样本，让同一个模型具备两种模式：需要解释时走完整模式，追求速度时走快速模式。快速模式正好交给研究点 3 使用。

“前 / 后 / 无依据 / 多任务”四种设置本身就是一组很好的消融实验，可以放进论文。

与 Guo 2026 的区别：他们的推理链由 GPT-4o 生成，没有逐条核验；你的依据由数据计算后填入模板，每一句都能回溯到数据，更可信。这一点也是创新点之一（见 2.11）。

## 2.6 小样本与未见组合的泛化策略

| 方案 | 做法 | 来源 | 评价 |
|---|---|---|---|
| ★ a 属性分解 | 按部件 / 轴 / 模式 / 程度分别学习，再在输出时组合 | 已定主线；Zhao 2025、Han 2026 的属性化零样本思路【文献夹】 | 核心方法 |
| ★ b 轻量数据增强 | 窗口随机平移、小幅缩放、叠加微小噪声 | 常规做法 | 简单有效；注意噪声幅度要远小于“噪声类故障”的最轻档，否则会污染标签 |
| c 上下文示例 | 推理时在提示里附一两个同类故障的参考样本 | LLM 的 in-context learning | 可作为 S5 小样本实验的一种变体 |
| d 课程学习 | 先学容易的故障，再学难的 | Lin 2026 的分阶段训练【文献夹】 | 可选，收益不确定 |
| e 元学习 / 原型网络 | 判别式小样本方法 | 小样本学习经典方法 | 不属于 LLM 路线，作为对照方法即可 |

**推荐 a + b**，c 作为 S5 的实验变体。

## 2.8 对照组与消融（写进技术路线即可，开题不必展开）

**对照组**：① 1D-CNN / Transformer + 分类头；② 同一编码器 + LLM + 分类头；③ 纯提示 LLM（只给统计摘要文本，不微调）；④ 属性原型零样本方法（Han 2026 思路）；⑤ 本文方法。其中 ② 对 ⑤ 证明“生成式”的作用，③ 对 ⑤ 证明“对齐训练”的必要性。

**消融**：去掉统计摘要文本、去掉机理提示、去掉依据（只输出结论）、单阶段训练、去掉层标识、去掉基线差分（这一项同时检验研究点 1）。

**指标**：各字段准确率、整体完全匹配率、未见组合准确率（S2–S4）、不同训练轮数下的性能曲线（S5）、依据与机理规则的一致率、格式错误率。

## 2.9 收敛后的技术路线（可直接改写进开题报告）

> 针对真机故障样本有限、实际故障类型开放的问题，构建融合时序—语义对齐与机理知识的生成式故障诊断模型。输入端采用通道独立的分块编码器，将研究点 1 得到的分层故障表征映射为带通道名与层级标识的时序 token，并辅以窗口统计量生成的文本摘要；以属性—机理描述表作为系统提示注入领域知识。训练采用两阶段策略：第一阶段冻结大语言模型，以数据驱动模板自动生成的“信号—描述”对训练编码器与投影层，实现时序与语义空间对齐；第二阶段以低秩适配（LoRA）微调，使模型先生成诊断依据，再生成部件、轴、模式、程度等结构化结论，并混入仅输出结论的样本，使模型兼具完整解释与快速诊断两种模式，同时通过约束解码保证输出合法。通过属性分解实现对未见故障组合的泛化，在部件组合、轴留出、程度外推和小样本等划分下验证。

**关键问题**：一是多通道、多速率闭环飞行时序与语言语义空间的对齐；二是小样本条件下对未见故障组合的泛化与可信解释。

**预期成果**：一种面向多旋翼无人机的结构化生成式故障诊断方法；与判别式及纯提示方法的对比实验结果。

## 2.10 已确认事项（第二轮）

1. 混合输入：接受。Chen 2027 也采用了类似的混合提示：统计文本提供宏观背景，主要依靠连续时序向量；并指出稀疏窗口的统计量方差大，单独依赖容易误导模型【文献夹】。这正好支持“嵌入为主、文本为辅”。
2. 两阶段训练：接受。
3. 模型规模：主实验 1.5B–4B，7B–8B 作上界：接受。
4. 依据顺序：依据在前 + 混入“只输出结论”样本的双模式（见 2.5 补充）。

## 2.11 研究点 2 的创新点在哪里

先说清楚**不算创新**的部分，答辩时不要把它们当创新点讲：patch-MLP 编码器、投影层、两阶段训练、LoRA 微调。这些是多模态 LLM 的通用组件，属于“方法组成”。

**可以作为创新点的有两条**，按重要性排序：

**创新点 A：面向未见故障组合的属性化结构化生成式诊断**
- 已有的属性化零样本诊断（Zhao 2025、Han 2026）都是判别式的：先预测属性，再与类别原型匹配。已有的生成式 LLM 诊断（AeroGPT、InstructTime、Guo 2026）输出的又是整体类别标签，没有拆分属性。
- 你的方法把两者结合起来：LLM 按“部件 / 轴 / 模式 / 程度”逐字段生成，并用约束解码保证每个字段取合法值，从而能输出训练时从未出现过的属性组合。
- 对应的实验是 S2–S4 留出，对照组是分类头和属性原型方法。

**创新点 B：数据驱动、可验证的诊断依据生成与训练**
